# Async Runtime (C++20)

Асинхронный рантайм на основе C++20 coroutines.  
Поддерживает кооперативную многозадачность, собственные планировщики и примитивы синхронизации без опоры на блокирующие системные вызовы.

---

## Обзор

Проект реализует модель асинхронного исполнения в пользовательском пространстве. Задачи запускаются через планировщики, сами добровольно отдают управление и не требуют отдельного потока на каждую операцию.

Основные части проекта:

- **coro** — интерфейс корутин и запуск асинхронных задач
- **sched** — планирование и исполнение задач
- **sync** — примитивы синхронизации для coroutine-friendly кода

---

## Возможности

- C++20 stackless coroutines
- Кооперативная многозадачность через `yield`
- Подключаемые планировщики
- Интрузивное хранение задач без лишних аллокаций
- Примитивы синхронизации, пригодные для асинхронного кода
- Go-like интерфейс для запуска задач

## Архитектура

### Планировщики (`sched`)

Базовая абстракция — `sched::Resumable<Scheduler>`.

Она описывает единицу работы, которую можно возобновить на конкретном планировщике.

Планировщик обязан поддерживать:

```cpp
void spawn(Resumable<Scheduler>&);
````

#### Реализации

* **RunLoop**

  * Однопоточный планировщик
  * Детерминированное исполнение
  * Удобен для тестов и простых сценариев

* **ThreadPool**

  * Фиксированное число рабочих потоков
  * Параллельное исполнение задач
  * Подходит для compute-bound нагрузки

#### Особенности

* Используются интрузивные структуры данных
* Нет лишних аллокаций на каждую задачу
* Планировщики можно расширять и заменять

---

### Корутины (`coro`)

Асинхронной функцией считается функция, возвращающая `coro::Coroutine` и использующая `co_await` / `co_return`.

Пример:

```cpp
coro::go(pool, [] -> coro::Coroutine {
    std::cout << "Hello" << std::endl;

    coro::go([] -> coro::Coroutine {
        std::cout << "Inner task" << std::endl;
        co_return;
    });

    co_return;
});
```

#### API

* `coro::go(scheduler, fn)` — запуск корутины на заданном планировщике
* `coro::go(fn)` — запуск с наследованием планировщика от родительской корутины
* `co_await coro::yield()` — добровольная передача управления

#### Особенности

* Корутины не возвращают значения
* Необработанное исключение завершает программу
* Время жизни корутины управляется рантаймом

---

### Синхронизация (`sync`)

Примитивы синхронизации рассчитаны на использование внутри корутин и не должны блокировать поток исполнения.

#### Event

Одноразовое событие:

```cpp
sync::Event event;

coro::go([&] -> coro::Coroutine {
    co_await coro::yield();
    event.emit();
});

co_await event.wait();
```

#### Mutex

Примитив взаимного исключения:

```cpp
co_await mutex.lock();
// critical section
co_await mutex.unlock();
```

#### Buffered Channel

Буферизованный канал в стиле Go:

```cpp
auto ch = sync::BufferedChannel<int>(2);

co_await ch.send(1);
co_await ch.send(2);

std::cout << co_await ch.recv() << std::endl;
std::cout << co_await ch.recv() << std::endl;
```

* Фиксированный буфер
* Без `close()`

## Принятые решения

* **Кооперативное планирование**
  Задачи сами уступают управление, вместо того чтобы вытесняться планировщиком.

* **Интрузивные структуры**
  Минимизируют накладные расходы и число аллокаций.

* **Разделение ответственности**
  Модель корутин, планирование и синхронизация отделены друг от друга.

* **Отказ от блокирующих примитивов**
  `std::mutex` и похожие механизмы внутри корутин не используются.

---

## Ограничения

* Коррутины не возвращают результат напрямую
* Нет structured concurrency
* Нет интеграции с IO
* `ThreadPool` не рассчитан на высокую нагрузку
* Канал не lock-free, а мьютекс lock-free, только если аллокатор lock-free

---

## Возможные расширения

* Structured concurrency
* Планировщик с поддержкой IO
* Таймеры и отложенное исполнение
* Lock-free примитивы синхронизации
* Более масштабируемые стратегии планирования
* Дополнительные примитивы, например RWLock и WaitGroup
* flat-combining в Mutex
